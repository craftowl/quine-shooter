## 1. 何を作るか（WHAT）

- ジャンル: 弾幕シューティング（縦スクロール）
- 画面: 縦画面。ゲーム内の座標は **480×640** に固定し、ウィンドウに表示するときに拡大する
- ひとことで言うと: **自分のソースコードでできた敵を撃ち崩す弾幕STG**
- 核になる要素: **Quine の要素**
  - 敵の体は、その敵の動きを実装している実際の C++ ソースの文字で描いた絵にする（IOCCC の作品のように、コードで敵の形を描く）
  - 1文字ずつに当たり判定がある
  - 弱点の文字 `$` を壊すとパワーアップアイテムが手に入る
  - 詳細は [ADR 0002](decisions/0002-quine-enemy-text.md)
  - 文字を壊すと動きが変わる仕組み（段階3）は今回やらない
- 表現: 自機・敵・弾・UI をすべて文字で描く

### ゲームの流れと規則

数値はすべて調整値の JSON に書く（置く値の一覧は [design.md](design.md) §5）。

#### 構成

- 3ステージで構成する。ステージは画面に「STAGE n」と出る区切りで、中身は複数のウェーブ（一緒に出てくる敵のまとまり）でできている
- ステージ1と2は雑魚だけ。ステージ3は、雑魚のウェーブのあとにボスが出る
- 雑魚は3種類で、ステージごとに1種類ずつ新しい雑魚が加わる。ボスは1体
- 通しで遊んで約5分を目安にする（完成条件には含めない）
- 次のウェーブは、今のウェーブの敵がすべていなくなる（倒すか、画面の外に出る）か、ウェーブごとの制限時間が過ぎたら始まる。ボスのウェーブには制限時間を付けない
- ステージの区切りでは、画面を切り替えずに、残った敵と敵弾を消し、「STAGE n」を一定時間表示してから次のステージを始める。その間も自機は動かせる

#### 勝ち負け

- ボスを倒したらクリア。画面の敵弾を消し、「ALL CLEAR」を一定時間表示してからリザルトへ進む。その間も自機は動かせる
- 残機制にする。敵弾か敵の体（文字のマス）が自機の当たり判定に当たると1機減り、残機が0の状態で当たるとゲームオーバー
- やられたら、画面の敵弾をすべて消し、開始位置（画面下の中央）から復活する。復活したあとは一定時間無敵にし、点滅で示す。ウェーブの進行は止めない
- ゲームオーバーでは CONTINUE と GIVE UP を選べる
  - CONTINUE：残機を最初の数に戻し、その場から再開する。ショットの段階はそのまま。その時点のスコアでハイスコアを更新してから、スコアを0に戻す
  - GIVE UP：リザルトへ進み、スコアが確定する

#### 敵の倒し方とパワーアップ

- 自機の弾が当たった文字は1発で壊れて消え、弾も消える。敵の HP は、当たるたびに1減る
- HP が0になるか、文字がすべて壊れたら敵が倒れ、残りの文字も消える
- `$` も1発で壊れ、HP も1だけ減る。壊すと、その場所にパワーアップアイテムが出る。敵が先に倒れたら、残った `$` からアイテムは出ない
- アイテムは文字 `P` で描く。下へ落ちていき、自機が触れたら取れる。画面の下から出たら消える
- アイテムを取るとショットの段階が1つ上がり、一度に撃つ弾の列が増える。段階には上限があり、上限のときに取ると点が入る
- やられるとショットの段階が1つ下がる（最初の段階より下にはならない）
- ボスは、HP が決まった割合を下回るたびに次の攻撃に変わる。HP による変化なので、§4 の「文字を壊すと敵の動きが変わる仕組み」には当たらない

#### スコア

- 文字を1つ壊すごとに小さな点、敵を倒すと大きな点が入る（どちらも敵ごとに決める）
- ハイスコアは起動中だけ保持する（§4）

#### 操作

| 操作 | キー |
| --- | --- |
| 移動 | 矢印キーか WASD |
| 低速移動 | Shift を押している間 |
| ショット | なし（常に自動で撃ち続ける） |
| ポーズと再開 | Esc |
| メニューで選ぶ | 上下の矢印キーか W と S |
| メニューで決める | Enter、Space、Z のどれか |
| 消音と解除 | M |

- Esc ではゲームを終了しない。デスクトップ版は、タイトル画面の「終了」か、ウィンドウの閉じるボタンで終わる。Web 版のタイトル画面には「終了」を出さない
- ポーズ中は「ゲームに戻る」か「タイトルへ戻る」を選べる
- リザルト画面では、決定のキーでタイトルへ戻る
- 消音を切り替えたときは「SOUND OFF」「SOUND ON」を一瞬表示する。タイトル画面に「M: MUTE」と書く

#### 画面に出す情報

- ゲーム中は、画面の上の1〜2行に、スコア、ハイスコア、残機、ショットの段階を文字で重ねて表示する。ボスが出ているあいだは、ボスの HP を文字のゲージで表示する
- 自機の当たり判定は、小さな点として常に表示する（文字で描く）
- 各画面の並びと、自機や当たり判定を描く文字は、画面を作るタスクで決める

## 2. なぜ作るか（WHY）

- プログラマー職の就活ポートフォリオとして提出する
- 見せたいもの: **仕様駆動開発の過程そのもの**。設計は人が行い、実装は AI に任せる
  - 評価してもらいたいのは「AI を使ったこと」ではなく、次の3点
    1. 実装を任せられる密度の仕様と設計を人が書けること
    2. AI の出力を仕様に照らして検証し、ズレを直したこと
    3. その判断の記録（ADR、検証ログ）が残っていること

## 3. 完成条件

次の8つを満たしたら完成と宣言する。これ以外はすべておまけ。

- [ ] タイトル画面 → ゲーム → リザルト → タイトル、が一周する
- [ ] 負ける条件と、勝つ（またはスコアが確定する）条件がある
- [ ] ステージまたはウェーブが3つ以上ある
- [ ] 音が鳴る（BGM 1曲、SE 3種類）
- [ ] Windows 版が、ダブルクリックして起動する。作者の Windows PC で起動を確かめ、実行ファイルが頼る DLL が OS に標準で入っているものだけであることを CI で確かめる
- [ ] 公開した URL をブラウザで開いて遊べる（公開先は GitHub Pages。[ADR 0004](decisions/0004-platforms.md)）。作者の Mac と Windows 11 のブラウザで確かめる
- [ ] README の手順どおりに、Windows 版と Web 版のビルドが通ることを、クリーンな環境で確かめた（CI で確かめてよい）
- [ ] tasks.md のタスク（「完成のあとのタスク」の節にあるものを除く）の受け入れ基準がすべて検証済みで、その記録が `docs/verification/` に残っている

### 性能の目標（完成条件には含めない）

- 弾を1万発出したまま 60fps を保つ（1フレームの更新と描画が約16.7ms 以内）
- そのときも、1フレームの確保回数は0（[ADR 0007](decisions/0007-dynamic-allocation.md)）
- 測る条件：デスクトップ版の RelWithDebInfo。測った値は CPU、OS、ビルド構成、弾数と一緒に書く（AGENT.md）
- 弾を1万発出す方法（デバッグ機能など）は、計測するタスクで決める

## 4. やらないこと

| 項目 | 理由 |
| --- | --- |
| セーブ機能 | 1プレイで完結する。ハイスコアも起動中だけ保持する |
| 設定画面 | 解像度は固定。音は M キーで消音と解除を切り替えるだけにし、音量そのものは調整値で決める |
| ゲームパッド対応 | 対応自体は簡単だが、動作を確かめる手間に見合わない |
| 文字を壊すと敵の動きが変わる仕組み | Quine の要素は「コードで敵の形を描く」までにとどめる |
| ソースを手で絵の形に整形する（IOCCC 流） | AI に実装を任せられない（[ADR 0002](decisions/0002-quine-enemy-text.md)） |
| 日本語の表示 | ゲーム内は ASCII 文字だけにする。フォントが小さく済み、Web 版のサイズも抑えられる |
| 難易度の選択 | 難易度は1種類だけ。調整の手間が倍になるのを避ける |
| 自機の選択 | 自機は1種類だけ |
| リプレイ機能 | 記録を保存する場所がなく（セーブ機能は作らない）、記録と再生の画面を作る手間に見合わない |
| オンラインランキング | サーバーが必要になる |
| スマホ・タッチ操作 | Web 版は PC のブラウザだけを対象にする |
| マスクを描く専用エディタ | マスクはテキストエディタで手で描く |
| 複数のボス | ボスは最終ステージの1体だけ。途中のステージは雑魚だけで区切る |
| 凝った背景 | 背景は流れる文字（`.` や `:` の星）だけにする |

### やることとして残すもの

- 調整値の JSON のホットリロード。ゲームを止めずにバランスを調整でき、プレイテストが速くなる
