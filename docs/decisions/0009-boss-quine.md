# ADR 0009: ボスの体を本物の Quine にする

- 日付: 2026-10-03
- 状態: 採用（2026-10-05。AI が下書きし、人が決めること5つを人が決めて、人が採用した）

## 背景

[ADR 0002](0002-quine-enemy-text.md) では、敵の体を「その敵の挙動のコード」で描くと決めた。コードの空白・タブ・改行の並びを空白1つにまとめ、マスクの `#` に詰める。

T15a の検証のときに、作者が「コードの空白（`Vector2 boss_ok_move` の間の空白）が体のテキストに出るのはおかしい」と感じた。Quine を形に並べる記事（https://qiita.com/yoshi389111/items/c263512e523deadc01d0 ）を参考に相談し、次のことを決めた（2026-10-03、人が決めた。[tasks.md](../tasks.md) の T15q）。

- ボスの体のテキストを、本物の Quine にする。テキストをコンパイルして実行すると、同じ形の自分を出力する
- Quine は自分を出力するだけのプログラムで、ボスの挙動のコードは含めない
- 対象はボスだけ。雑魚は ADR 0002 の方式のまま
- 言語は C++
- Quine のソースをファイルとしてリポジトリに置き、README に手順を書く。CI で毎回、コンパイル・実行・比較をする

記事の Quine（JavaScript）は、形に並べたテキストの大部分をテンプレート文字列に入れ、空白を消してから `eval` で動かす。C++ には `eval` がないので、同じ方法は使えない。そこで、C++ で作れるかを試した（T15q、半日の試作。試作のコードは作業用の場所に置き、コミットしていない）。

## 試作の結果（T15q）

環境：macOS 27.0.1、MacBook Pro（Apple M1 Max）、Apple clang 21.0.0（`-std=c++20`）。生成ツールは使い捨てとして Python 3.14.7 で書いた。

### 仕組み

プログラム F を、マスクの `#` に左上から1文字ずつ置く。`.` には空白、`$` には `$` を置く。

```text
F = P + R"( + D + )" + Q
D = P + R"( + @ + Q + @ + M + 詰め物の *
```

- P と Q は、自分を出力するコード（出力部）。P は `extern"C"{int(putchar)(int);}char(s)[]=`（39 文字）、Q は `main`（307 文字。弱点の `$` に対応すると 335 文字）。これに、形に応じた詰め物のコメントが加わる
- D は生文字列の中身。生文字列の中なら、穴や改行が入ってもよい。M はマスクのランレングス（`#` は大文字、`.` は小文字、`$` は数字。記事と同じ考え方）
- 出力部は、生文字列から空白と `$` を取り除いて D を取り出し、P、Q、M に分けて F を組み立て直し、M のとおりに並べて出力する
- 出力部は、空白なしでコンパイルできるように書く（`int(main)()`、`int(c)=0` のように、宣言の名前を括弧で囲む。文字のリテラルを使わず、文字は数で書く）
- 出力部の字句（`putchar` など）が、形の穴や行の切れ目をまたぐとコンパイルできない。生成ツールは、またがないように、コメント `/*…*/` を詰め物として入れる。コメントの中は穴や改行をまたいでよい。弱点の `$` のマスも、出力部の中ではコメントの中に来るように詰める。詰め方は、いちばん短く終わるものを探す（字句の番号、マスの位置、コメントの中かどうか、の3つを状態にした探索）

### 気づいたこと

- `-Wall -Wextra -Wpedantic` では、警告が5件出る（形に並べたことによる字下げの警告 `-Wmisleading-indentation` が4件、空の `for` の警告 `-Wempty-body` が1件）。Quine はゲームとは別のプログラムなので、ゲームの警告の設定（警告をエラーにする）をそのまま当てはめるかは、決める必要がある。空の `for` は書き方を変えれば消せる
- gcc と MSVC では試していない。`extern"C"{int(putchar)(int);}` は標準の書き方なので、通る見込み
- 生成したファイルの行末には、マスクの `.` の分の空白がある。エディタが行末の空白を消すと、Quine でなくなる。改行コードが変わっても（Windows の `core.autocrlf=true` で取り出して CRLF になるなど）、Quine でなくなり、埋め込んだ体のテキストに `\r` が混ざる。守る方法（`.gitattributes` で改行を変えないようにするなど）は、T15c で置き場所と一緒に決める（文書のレビューの指摘を受けて足した。2026-10-05、人が決めた）
- 体のテキストの `#` のマスには空白が入らない（空白が出るのは `.` のマスだけ）。作者が感じた「コードの空白が出る」問題は、ボスでは起きない

## 決定

- ボスの体のテキストは、生成ツールで作った C++ の Quine にする。雑魚は ADR 0002 のまま
- ボスのマスクは、`#` のマスが 2×（P＋Q）＋M＋10 以上（今の出力部で、弱点ありならおよそ 900 以上）で、7文字以上の横の並びが十分にある形にする。必要なマス数は、出力部を短くすれば減る

### 決めたこと（2026-10-05、人が決めた。T15q の試作のあと）

1. **ボスを QUINE 範囲の規則と quine_pack の検査からどう外すか**（T15q の確かめること7）
   - **決定**：ボスは QUINE 範囲を使わない。ボスの挙動のコードは普通のコード（`QUINE-BEGIN` で囲まない）にし、体のテキストは生成した Quine のファイルから取る。AGENT.md の「Quine の敵」の QUINE 範囲の規則と、ADR 0002 の QUINE 範囲に関するルール（1・3・7、ルール5のうち QUINE 範囲に書いてよい数値と大文字の名前の制限）は、雑魚だけに当てはめる。マスクに関するルール（2・4・6）と、ルール5の「調整値は JSON で定義する」はボスにも当てはめ、ボスの挙動のコードにも難易度の数値を直接書かない。quine_pack は、ボスのマスクも今までどおり検査し（使える文字、行の長さ、`#` の数、大きさの上限）、そのうえで Quine のファイルを読んで、テキストがマスクの形（`.` は空白、`$` は `$`、`#` は空白でない文字）になっているかを確かめる（T15a のあとの文書のレビューの指摘を受けて、ほかの文書にそろえた。2026-10-05、人が決めた）
   - 見送った案：ボスの挙動のコードも QUINE 範囲に書いて検査するが、体のテキストには使わない（表示しないコードに、表示のための制約がかかるだけで、意味が薄い）
2. **作るタイミング**
   - **決定**：前もって生成し、Quine のファイルをリポジトリに置く。README からそのまま指せて、ゲームのビルドはそのファイルを埋め込むだけなので、Web 版のビルド（emcmake）でも問題がない。CI は、生成し直して同じになることと、コンパイル・実行・比較で自分を出力することを確かめる
   - 見送った案：ビルドのたびに生成する（生成ツールを C++ で書くと、emcmake では動かせない。README から指すには、別に置き場所が要る）
3. **本番の生成ツールを何で書くか**
   - **決定**：C++。デスクトップのビルドでだけ作る別の実行ファイルにし、開発者が動かす（emcmake では作らない）。CI では ubuntu の普通のコンパイラで作り、生成し直す。依存は増えない
   - 見送った案：Python（試作をそのまま育てられるが、依存の追加になる）、CMake スクリプト（詰め方の探索は状態が約 100 万あり、遅い見込み）
4. **形の数**
   - **決定**：1つ。実行すると、まったく同じ形の自分を出力する（T15q で決めた「同じ形の自分を出力する」のとおり）。あとで増やすことはできる
   - 見送った案：攻撃の段階ごとに形が巡る（出力が自分と同じにならない、巡回する Quine になる）
5. **Quine に当てはめる警告の設定**
   - **決定**：ゲームと同じ設定（`-std=c++20 -Wall -Wextra -Wpedantic -Werror -fno-exceptions`）に、`-Wno-misleading-indentation` だけを足して CI でコンパイルする。形に並べる以上、字下げの警告は避けられないため。空の `for` の警告は、生成ツールの出力部の書き方を直して消す。ただし、試作で確かめたのは clang だけ。gcc は、宣言の名前を括弧で囲む書き方（`int(c)=0` など）に `-Wparentheses`（`-Wall` に含まれる）を出すおそれがある。T15c で CI（ubuntu の g++）でも確かめ、形に並べるための書き方が出す警告がほかにあれば、それだけを外す。外す警告は T15c で人が決める（文書のレビューの指摘を受けて足した。2026-10-05、人が決めた）

## 理由

- C++ でも、生文字列とコメントの詰め物を使えば、形を持った Quine を自動で作れることが分かった
- 手で整形しないので、ADR 0002 で手で整形する案（B）を見送った理由（AI に任せられない、コードを直すたびに形を作り直す）は当てはまらない
- 雑魚の大きさ（240 マス）には入らないので、ボスだけにする

## 影響と注意点

- ADR 0002、AGENT.md の「Quine の敵」と「検査」、design.md §4・§5 は、この ADR の採用と一緒に直した（2026-10-05）
- ボスの Quine を作るタスク T15c（C++ の生成ツール、Quine のファイル、README の手順、CI のステップ、quine_pack のボスの扱い）を、T15b のすぐあとに足した（人が決めた）。ボスの形は仮のもので作り、T22（ボス）で本物の形に差し替える
- quine_pack とそのテスト（`ok` の `boss_ok` などは、今のボスの扱いを前提にしている）は、T15c で直す。それまで quine_pack は、`boss_` で始まる敵も雑魚と同じく扱う。T15b ではボスを置かないので、困らない
