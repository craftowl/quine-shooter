# ADR 0004: 配布対象のプラットフォーム

- 日付: 2026-09-22
- 状態: 採用
- 更新: 2026-09-23（表の「ビルド方法」の列を「配布物をビルドする場所」にそろえた。Web 版の公開先を追記）
- 更新: 2026-10-02（Windows 版を CI でビルドする理由を書き換えた。作者が Windows 11 の PC を持っていて、「手元に Windows 環境がなくても」が今の状況と合わなくなったため。T10）

## 決定

| プラットフォーム | 位置づけ | 配布物をビルドする場所 |
| --- | --- | --- |
| **Web**（PC のブラウザ） | 配布の主力 | GitHub Actions（Emscripten） |
| **Windows** | 配布 | GitHub Actions |
| macOS | 開発環境のみ（配布しない） | 配布しない（開発中は手元でビルド） |

- 雛形の段階から Web 版のビルドを通す
- デスクトップと Web でメインループの書き方が違う部分は、`main.cpp` の1か所だけで切り替える
- Web 版は GitHub Pages で公開する。GitHub Actions から、公式のアクション（`actions/` で始まるもの）だけで公開する

## 理由

- 採用担当は、知らない実行ファイルをダウンロードして起動してくれないことがある。URL を開くだけで遊べる Web 版が、ポートフォリオとして一番見てもらいやすい
- 採用担当の PC は Windows が多いと考えられる。Windows 版は CI でビルドし、配布物を毎回同じクリーンな環境で作る。開発に使う Mac とは別に、Windows 版のビルドが通ることを push のたびに確かめられる。作者の Windows 11 の PC は、できた配布物の起動を確かめるのに使う
- ブラウザではメインループを `emscripten_set_main_loop` に渡す形になる。後から対応すると設計の手戻りになるので、最初から両対応にする
- GitHub Pages なら、Web 版のビルドと同じ GitHub Actions から公式のアクションだけで公開でき、依存（ADR）を増やさずに済む。無料プランでは、リポジトリを公開することが前提になる

## 検討して見送ったもの

| 候補 | 見送った理由 |
| --- | --- |
| macOS 版の配布 | 署名していないアプリは起動時に警告が出て、開き方の案内が要る |
| Linux 版の配布 | 採用担当が使う可能性が低い |
| スマホのブラウザ | タッチ操作に対応しない（[requirements.md](../requirements.md) のやらないこと） |
| itch.io で公開する | アップロードが手作業になるか、公式以外のツール（butler）が要る |
