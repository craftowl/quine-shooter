## 前提（Step 0）

| 項目 | 決定 |
| --- | --- |
| 目的 | プログラマー職の就活ポートフォリオ |
| 期限 | なるべく早く |
| 作業時間 | 週40時間以上 |

ガイド『エンジンレス開発ガイド — raylib/SDL + C++/Rust で小規模ゲームを1本作る』の実装ロードマップ（週10〜15時間 × 8週間 ＝ 約80〜120時間）を週40時間で割ると **約3週間** になる。
予備を含めて **4週間での完成** を目標にする。

## 決定

| 分類 | 採用 | バージョン（固定） | 用途 |
| --- | --- | --- | --- |
| 言語 | C++20 | — | 本体 |
| ビルド | CMake + FetchContent | CMake 3.25以上 | 依存の取得とビルド |
| Web 版のビルド | Emscripten（emsdk で導入） | `6.0.9` | Web 版のコンパイル。手元でも CI でも emsdk で入れる |
| 描画・入力・音 | raylib | `6.0` | ゲーム本体の土台 |
| データ | nlohmann/json | `v3.12.0` | 調整値・ウェーブ定義の外部化 |
| デバッグUI | Dear ImGui | `v1.92.9b` | Debug と RelWithDebInfo のみ |
| デバッグUI | rlImGui | `Raylib_6_0` | ImGui と raylib の接続。Debug と RelWithDebInfo のみ |
| フォント | JetBrains Mono | `v2.304` | 画面の文字。Regular の TTF とライセンス文（SIL OFL 1.1）を `assets/fonts/` に入れる。入手先：https://github.com/JetBrains/JetBrainsMono/releases/tag/v2.304 |

ライブラリはすべて FetchContent でタグを固定して取得する。ブランチ名は指定しない。

### バージョンの決め方

| 対象 | 決め方 |
| --- | --- |
| ライブラリ、フォント、Emscripten（emsdk）、GitHub Actions のアクション、開発用のツール | バージョンを固定する |
| CMake、コンパイラ | 最低バージョンを書く。コンパイラの最低バージョンは、Windows 版のコンパイラを決めるときに書く |
| CI のランナーイメージ | 名前で指定する。`windows-latest` のように中身が変わる名前は使わない。具体的な名前は CI を作るときに選ぶ |

GitHub Actions のアクションは、タグではなくコミットの SHA（40桁）で固定し、バージョンを注釈に書く（例：`uses: actions/checkout@<SHA> # v5.0.0`）。タグは付け替えられるので、同じタグでも中身が変わることがある。リポジトリの設定（Settings → Actions → General）で、SHA で固定することを必須にし、許可するアクションを絞る（[GitHub の 2025-08-15 の変更](https://github.blog/changelog/2025-08-15-github-actions-policy-now-supports-blocking-and-sha-pinning-actions/)で設定できるようになった）。SHA で固定していないアクションを使うと、ワークフローが失敗する。許可するのは `actions/*` だけにする（T11 で決めた）

手元の環境のバージョン（2026-09-24 に確かめた。デスクトップ版は T01 でビルドした）：CMake 4.2.1、Apple clang 21.0.0（Command Line Tools 27）、Emscripten 6.0.9（emsdk 6.0.9 で入れたもの。まだビルドしていない）

### ビルド構成

| 構成 | 用途 | 最適化 | `assert` | デバッグ機能 |
| --- | --- | --- | --- | --- |
| Debug | 開発 | なし | あり | あり |
| RelWithDebInfo | 計測とプレイテスト | あり | なし | あり |
| Release | 配布 | あり | なし | なし |

デバッグ機能は `DEBUG` で切り替え、CMake で `$<$<CONFIG:Debug,RelWithDebInfo>:DEBUG>` と定義する。CMake の Debug ビルドは `DEBUG` を定義しないため。

## 理由

### C++
- プログラマー職、特に国内ゲーム業界の実務言語であり、そのまま業務スキルとして説明できる
- Unreal Engine の実務に接続できる

### raylib
- 学習コストが低く、完成までの距離が最も短い。期限を優先する今回の方針に合う
- 公開関数が約500個で、ヘッダが1ファイル（`raylib.h`）。AI にAPIの全体像を渡しやすく、誤用が減る
- SDL3 や sokol に比べて自分で書く量が少ない。浮いた時間を弾の大量処理、当たり判定、設計ドキュメントといった見せたい部分に回す

### nlohmann/json
- ヘッダオンリーで導入が容易
- 調整値を外部化すると、再ビルドせずにバランス調整できる。ホットリロードにもつながる
- 例外を使わない方針に合わせ、`JSON_NOEXCEPTION` を定義してビルドする。ただし、これは例外を `std::abort()` に置き換えるだけなので、失敗を戻り値で扱うための読み方を [ADR 0006](0006-error-handling.md) で決めている

### Dear ImGui + rlImGui
- 当たり判定の可視化、パラメータの実行時調整、オブジェクト数の表示に使う。いずれも開発を速くするための投資
- ゲーム業界の開発ツールで広く使われていて、面接で話題にしやすい
- 配布物に含めないよう、Debug と RelWithDebInfo でのみリンクする

### ビルド構成
- Debug ビルドは最適化されないので、そこで測った数値はポートフォリオに載せられない。最適化したビルドでも FPS やオブジェクト数の表示を使えるように、RelWithDebInfo にもデバッグ機能を入れる
- CMake に最初からある構成だけで済み、独自のオプションを覚えなくてよい

### Emscripten（emsdk）
- README の手順どおりに、どの OS でも同じバージョンを入れられる。Homebrew では、古いバージョンを指定して入れにくい
- 手元と CI で入れ方がそろうので、入れ方の違いによる差を気にしなくてよい
- 6.0.9 は、この ADR を更新した時点で手元にあったバージョン

## 検討して見送ったもの

| 候補 | 見送った理由 | 見直す条件 |
| --- | --- | --- |
| SDL3 / sokol | 自分で書く量が増え、期限に合わない | 完成後に移植すれば、その移植自体が設計力の証明になる |
| Rust | 国内ゲーム業界での採用事例が少なく、「なぜRust？」の説明が要る | — |
| raygui | デバッグ用途では ImGui の方が機能が多く、業界でも広く使われている | — |
| EnTT などの ECS ライブラリ | オブジェクトプールやエンティティ管理を自作する部分が見せ場なので、ライブラリに任せると意味が薄れる | — |
| doctest（単体テスト） | 期限を優先して初期導入は見送る | 当たり判定など純粋な関数のバグが続いたら追加する |
| Tracy（プロファイラ） | 初期の計測は自前の FPS・フレーム時間表示で足りる | 弾1万発を目標にした最適化の段階で検討する |
| デバッグ機能を Debug ビルドだけに入れる | 最適化したビルドで計測するときに、FPS やオブジェクト数の表示が使えない | — |
| Emscripten を Homebrew で入れる | 古いバージョンを指定して入れにくく、README の手順で同じバージョンを再現できない | — |
| GitHub Actions のアクションをすべて ADR に書く | `actions/checkout` のような公式の基本的なアクションまで書くのは、手間に見合わない | — |
| GitHub Actions のアクションを、完全なバージョンのタグ（`@v5.0.0` など）で固定する | 読みやすいが、タグは付け替えられるので、厳密には固定にならない | — |
| CMake とコンパイラもバージョンを固定する（CI では pip で決まったバージョンの CMake を入れるなど） | 再現性は上がるが、CI と手元でそろえる手順と ADR が増える。手元の CMake は Homebrew の更新で変わる | — |

## 影響と注意点

- rlImGui の `Raylib_6_0` タグと ImGui `v1.92.9b` の組み合わせは、雛形の作成時にビルドが通ることを確認する。通らなければ rlImGui 側が想定する ImGui のバージョンに合わせ、この ADR を更新する
- Emscripten 6.0.9 で Web 版のビルドが通ることを、雛形の作成時に確認する。CI では、emsdk のリポジトリを clone してインストールする公式の手順を使い（clone するときはタグ `6.0.9` を指定する）、公式以外のアクションは使わない
- 依存を追加するときは、ADR に書いてから追加する。対象は、ライブラリ、ツールチェーン、フォント、公式以外の GitHub Actions のアクション、開発用のツール。GitHub 公式のアクション（`actions/` で始まるもの）は、ADR に書かずに使ってよい。バージョンは「バージョンの決め方」の表に従う
