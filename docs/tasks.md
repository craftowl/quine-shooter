## 進め方

- 1回に1タスクだけ実装する（[AGENT.md](AGENT.md)）。上から順に進める
- T01 の前に git を始める（Step 6）。「一時的に足して戻す」確認と「差分を貼る」確認は、git があることを前提にする
- 「着手前に決めること」は、実装を始める前に人が決める。決まったら、このファイルか該当する docs に書いてから実装する
- 受け入れ基準の検証は人が行い、`docs/verification/<タスクID>.md` に記録する（[ADR 0005](decisions/0005-spec-driven-process.md)）。AI は下書きまで
  - 検証ログの先頭には、次の形で状態と分担を書く。下書きの間は「状態: 下書き（日付）」にし、人が判定を終えたら「検証済み（日付）」に変える

    ```
    > 状態: 検証済み（2026-09-24）
    > - 下書き: AI（Claude Code）
    > - 判定: 人（作者）
    ```

- 「確かめ方」の列の読み方
  - 「AI：」の行は、AI が実行した出力（コマンド、ログ）を検証ログの下書きに貼る。人はそれを見て判定する。必要なら人が自分で実行し直す
  - 「人：」の行は、AI には確かめられないもの（画面の見え方、操作の手触り、ブラウザでの動作）を表す
  - AI がサンドボックスの中でウィンドウを開けるかは、T01 で最初に確かめる。開けなければ、ウィンドウを開く必要がある「AI：」の確認は、人が行う
- T05 までは、画面の文字を raylib に組み込まれたフォントで描く。AGENT.md の「フォントは JetBrains Mono」の一時的な例外で、T05 で JetBrains Mono に切り替える

### T01 ビルドの土台とウィンドウ

**目的**：C++20、警告をエラーとして扱う設定、例外なしのビルドの上で、ウィンドウが開いて固定ステップのループが回る状態を作る。以降のすべてのタスクの土台になる。

**作業**

- 最初に、AI がサンドボックスの中でウィンドウを開けるかを確かめ、結果を完了報告に書く
- `CMakeLists.txt` を作る
  - C++20
  - FetchContent で raylib `6.0` をタグで取得する
  - 自分のコードにだけ `-Wall -Wextra -Wpedantic -Werror` と `-fno-exceptions` を付ける。raylib のヘッダでは警告を出さない
  - `$<$<CONFIG:Debug,RelWithDebInfo>:DEBUG>` を定義する
- `src/main.cpp` を作る
  - 先頭に、design.md §2 の形でプラットフォームの `#if` を作る。Web の分岐も書くが、動くことは T03 で確かめる
  - 480×640 のウィンドウを開く（大きさの決め方は T05 で決めるので、ここでは 480×640 のまま）
  - `InitWindow` の後に `SetExitKey(KEY_NULL)` を呼び、Esc で終了しないようにする（design.md §2）
  - ADR 0003 の固定ステップのループを、`src/core/` に置く
  - 画面に文字を1つ描く（動いていることが分かれば何でもよい）
- `README.md` に、デスクトップ版のビルド手順を書く

**着手前に決めること**

- 書式（インデントなど）：AI が決めて完了報告に書くか、clang-format を入れるか（入れるなら先に ADR が要る）。design.md §5
  - **決定（2026-09-24）**：AI が決めて完了報告に書く。clang-format は入れない
- CMake の最低バージョン：FetchContent の `SYSTEM`（外部のヘッダの警告を消す指定）は CMake 3.25 から。候補は、3.25 に上げる（ADR 0001 を直す。手元は 4.2.1。CI のランナーの CMake は T10 で確かめる）か、3.20 のまま別の書き方で警告を消すか
  - **決定（2026-09-24）**：3.25 に上げる。raylib 6.0 の CMakeLists.txt 自体が 3.25 を要求していた。ADR 0001 を直した
- `CMAKE_BUILD_TYPE` を指定しなかったときの扱い：指定しないと3つの構成のどれでもないビルド（`DEBUG` なし、`assert` あり）になる。候補は、既定の構成を CMakeLists.txt で決めるか、README で必ず指定させるか
  - **決定（2026-09-24）**：構成を1つだけ持つジェネレータ（Makefiles など）で指定がなければ Debug にし、そのことを設定のログに出す。README でも構成を指定する手順にする
- `src/core/` に置くファイルの名前と、公開する関数の形（C4）
  - **決定（2026-09-24）**：`src/core/fixed_step.h` と `.cpp`。`FIXED_DT` と `MAX_FRAME_TIME` を定数で持ち、クラス `FixedStep` の `[[nodiscard]] int advance(float frame_time)` が、経過時間（`MAX_FRAME_TIME` で打ち切る）を溜めて、このフレームで `update()` を回す回数を返す。`GetFrameTime()` を読んで `update(FIXED_DT)` を回数分呼ぶのは `main.cpp` の `frame()`

**受け入れ基準**

### T02 検査スクリプト

**目的**：AGENT.md の「検査」の表のうち、CMake のスクリプトで確かめるものを、ビルドのたびに確かめる。早く入れるほど、後のコードが最初から検査される。

**作業**

- CMake のスクリプト（`cmake -P` で動くもの）を作り、ビルドのたびに実行する
- 検査の対象は `src/` の `.h` と `.cpp`。外部のコードと生成したファイルは対象外
- スクリプトは、ビルドのたびに `src/` を自分で探して対象のファイルを集める（CMake の設定のときに作った一覧を使うと、あとから置いたファイルが見えない）
- 次の違反があれば、ファイル名と行番号を出してビルドを止める
  1. プラットフォームを判定するマクロ（`PLATFORM_WEB`、`__EMSCRIPTEN__`、`_WIN32`、`_MSC_VER`、`__MINGW32__`、`__APPLE__`、`__linux__`）が、`main.cpp` の先頭にある1つの `#if`（`#elif` と `#else` を含む）の外にある
  2. 使わない関数（ADR 0006 の表のうち、確かめ方が「スクリプト」の行）を使っている
  3. 入力・時間・乱数の関数（AGENT.md の「構造」の一覧）を、`main.cpp`、`src/core/`、`src/debug/` の外で使っている
- 500行を超えたファイルがあれば、警告だけを出す（`wc -l` と同じ数え方）

**着手前に決めること**

- スクリプトの置き場所（design.md §3 にない。`tools/` には quine_pack しかない）。候補：`cmake/`、`tools/checks/`。決めたら design.md §3 に足す
  - **決定（2026-09-24）**：`cmake/check_sources.cmake`。design.md §3 に足した
- 「`std::stoi` など、文字列を数値に変える関数」に何を含めるか。案：`std::stoi`、`stol`、`stoll`、`stoul`、`stoull`、`stof`、`stod`、`stold`。`atoi` や `strtol` のような C の関数も含めるか
  - **決定（2026-09-24）**：`stoi`、`stol`、`stoll`、`stoul`、`stoull`、`stof`、`stod`、`stold` に加え、C の `atoi`、`atol`、`atoll`、`atof`、`strtol`、`strtoll`、`strtoul`、`strtoull`、`strtof`、`strtod`、`strtold` も止める（C の関数は例外を投げないが、「数値は JSON から読む」は同じく当てはまる）
- コメントと文字列の中に出てくる名前も違反にするか（文字列の一致で判定するので、除くならその処理が要る）
  - **決定（2026-09-24）**：コメント（`//` と `/* */`）と、文字列と文字のリテラルの中身を除いてから検査する。生文字列 `R"(…)"` は扱わない
- 文字列の一致で起きる、すり抜けと誤判定への対処。次の案で判定する
  - **決定（2026-09-24）**：下の案どおりにし、さらに3つ足す。(1) 名前と `(` や `<` の間に空白があっても止める（`x.at (1)` など）(2) 文字列を数値に変える関数は `std::` がなくても止める（ADL で `stoi(s)` が通るため）(3) `#include <filesystem>` も止める
  - `.at(` と `->at(`、`.value(` と `->value(` を違反にする。`.value_or(` は違反にしない
  - `std::get<` と `std::get(` に加えて、`std::` を付けない `get<`（C++20 では ADL で `get<0>(t)` が通る）も違反にする。`get` の前が識別子の文字でないときだけ一致させる（`budget<` を止めない）。ただし nlohmann/json の `j.get<int>()` のような `.get<`、`->get<`、`.template get<`、`->template get<` は除く（ADR 0006 で、レビューで確かめることになっている）
  - `rand` は、前後が識別子の文字でないときだけ一致させる（`operand` や `random_seed` を止めない）
- 「`main.cpp` の先頭にある1つの `#if`」の「先頭」の決め方（案：`main.cpp` の中でプラットフォームのマクロを使う `#if` が1つだけで、その `#if` から対応する `#endif` までの外にマクロが出てこない）
  - **決定（2026-09-24）**：案どおり

**受け入れ基準**

| # | 基準 | 確かめ方 |
| --- | --- | --- |
| 1 | 違反のない今のコードで、ビルドが通る | AI：ビルドする |
| 2 | 上の違反 1〜3 の種類ごとに、違反を含むファイルを一時的に置くと、CMake の設定をやり直さずにビルドが止まり、ファイル名と行番号が出る。`->at(`、`get<0>(t)` のように、上で決めた形も止まる | AI：種類ごとに試して戻す。人：違反の見本と結果を検証ログで確かめる |
| 3 | 違反でないもの（`.value_or(`、`operand`、`std::get_if`、`j.get<int>()`、`j.template get<T>()`、`budget<`）は止めない | AI：一時的なファイルで試して戻す |
| 4 | 501行のファイルを置くと警告が出て、ビルドは止まらない | AI：試して戻す |

**見込みの行数**：約200行

### T05 画面の拡大とフォント

**目的**：ADR 0008 のとおり、480×640 の座標を拡大し、ウィンドウの実際の解像度で文字をくっきり描く。

**作業**

- 起動時にウィンドウの大きさを決める（デスクトップと Web）
- JetBrains Mono `v2.304` の Regular の TTF と `OFL.txt` を `assets/fonts/` に置き、出典とライセンスを記録する
- 拡大率に合わせた大きさ（12px × 拡大率）でフォントを読み込み、`Camera2D` で拡大して描く。文字を描く処理は `src/render/` に置く。T04 までの組み込みフォントを、JetBrains Mono に切り替える
- ファイルを実行ファイルの場所を基準に開く（ADR 0006）。Web 版ではファイルを仮想ファイルシステムに入れる

**着手前に決めること**（ウィンドウの大きさと Web の基準は、design.md §5 で「雛形を作るとき」に決めることになっている項目）

- ウィンドウの大きさの決め方（デスクトップと Web）。候補：画面に収まる最大の大きさ、決まった大きさ。最大にする場合、縦横比を 3:4 に保つか、余白をどう扱うか
- 拡大率の刻み：`LoadFontEx` のフォントの大きさは `int` なので、12 × 拡大率が整数にならないと読み込めない（たとえば 1.4 倍で 16.8px）。案：拡大率を 0.25 刻みにする。ウィンドウは 120m × 160m、フォントは 3m px になり、どちらも必ず整数になる（1.5 倍なら 720×960 と 18px）
- Web 版でファイルを開く基準。決めたら ADR 0006 と AGENT.md を直す
- `data/` と `assets/` の置き方。T12 のホットリロードを見越して決める。ビルドのときに実行ファイルの横へコピーすると、編集する `data/params.json` とゲームが読むファイルが別物になる。候補：シンボリックリンクにする、DEBUG のときだけソースの `data/` を読む（ADR 0006 の「実行ファイルの場所を基準に開く」の例外になるので、ADR の直しが要る）、など。Web 版は仮想ファイルシステムの上にあるので、ホットリロードはできない
- 素材の出典とライセンスを記録する場所（案：`assets/fonts/README.md`、プロジェクトの README）

**受け入れ基準**

| # | 基準 | 確かめ方 |
| --- | --- | --- |
| 1 | ウィンドウが、決めた方法で決めた大きさになり、起動したあとは変わらない | 人：デスクトップ版と Web 版で確かめる |
| 2 | フォントの大きさが 12 × 拡大率 px（整数）で読み込まれる | AI：起動時のログに出して確かめる |
| 3 | 480×640 の座標の四隅と中央に置いた文字が、ウィンドウの四隅と中央に出る | 人 |
| 4 | 拡大率が 1 でないときも、文字がにじまずに読める | 人（使ったモニターの解像度と拡大率を検証ログに書く） |
| 5 | 作業ディレクトリを変えて起動しても、フォントが読める | AI：別のディレクトリから起動する |

**わかっていること**

- デスクトップでは、`InitWindow` の前に `GetMonitorWidth()` などでモニターの大きさを取れない（GLFW の初期化が `InitWindow` の中で行われ、それまでは 0 が返る）
- Web の `GetMonitorWidth()` は JavaScript の `screen.width` を返す。ブラウザの表示領域（`window.innerWidth`）を返す関数は raylib にない
- `GetApplicationDirectory()` は、Web（wasm）では `"/"` を返す

**見込みの行数**：約200行

### T08 確保の回数を数える仕組み

**目的**：ADR 0007 のとおり、プレイ中に動的確保が起きていないことを、数えて確かめられるようにする。弾のプールより先に入れる。

**作業**

- `src/debug/` で、グローバルな `operator new` と `operator delete` を置き換え、確保の回数を数える。配列版、`nothrow` 版、アラインメント指定版、サイズを受け取る `operator delete` を含む。`#ifdef DEBUG` で囲む
- 確保してよい場面（起動時とデータの読み込み時）以外で確保が起きたら、`assert` で止める
- 1フレームの確保回数を、T04 のデバッグ表示に出す

**着手前に決めること**

- 「いまがデータの読み込み中かどうか」の区別のしかた（ADR 0007 で、このタスクで決めることになっている）。案：読み込みの間だけ有効にする RAII のガード、フラグを立てる関数の組
- 「起動時」がいつ終わるか（案：最初のフレームを始める直前）

**受け入れ基準**

| # | 基準 | 確かめ方 |
| --- | --- | --- |
| 1 | 何もしていないフレームで、確保回数が 0 と表示される | 人：デバッグ表示を見る |
| 2 | フレームの中で一時的に `std::vector` を確保すると、Debug では `assert` で止まり、RelWithDebInfo では回数が表示される | AI：一時的に足して試し、戻す。人：表示を見る |
| 3 | 読み込み中として扱う範囲の中の確保では止まらない | AI：試して戻す |
| 4 | Release には、この仕組みが入っていない | AI：シンボルかコードの `#ifdef` を確かめる |

**わかっていること**

- rlImGui は raylib の `MemAlloc`（中身は `malloc`）で確保している（`Raylib_6_0` のソースで確かめた）。ImGui も既定では `malloc` を使う。どちらも `operator new` を通らないので、この仕組みとはぶつからない

**見込みの行数**：約150行

### T09 自機の移動

**目的**：入力をフレームの最初に読んで `update()` に渡し、自機を文字で描いて動かす。雛形の最後のタスクで、ガイドの第1週の到達点（「矢印キーで動く。ブラウザでも動く」）にあたる。

**作業**

- フレームの最初に入力を読み（`src/core/`）、その結果を `update()` に渡す
- 入力の型が決まったら、ADR 0003 と design.md §1 のコード例を、入力を `update()` に渡す形に直す修正案を出す（今のコード例は `update(FIXED_DT)` だけで、入力を渡していない）。人が採用してから反映し、ADR 0003 に「更新」の行を足す
- 自機を文字で描き、矢印キーか WASD で動かす。Shift を押している間は低速にする
- 自機の当たり判定を、小さな点として常に表示する（文字で描く）

**着手前に決めること**

- 入力を渡す型の形（ほかのファイルから使う型なので、AGENT.md により人が決める）。押した瞬間の扱い（design.md §5）は T19 で決める。このタスクでは押し続けている間だけを使う
- 自機の速さなどの数値の置き場所。requirements.md §1 では「数値はすべて調整値の JSON に書く」が、JSON の形は T12 で決める。案：仮の定数でコードに書き、T12 で JSON へ移す
- 自機と当たり判定を描く文字（requirements.md §1 では画面を作るタスクで決めることになっている。このタスクでは仮の文字でよいか）
- 画面の端で止めるか（requirements.md に書かれていない）
- 斜めに動くときの速さ（縦横と同じ速さにそろえるか）
- 受け入れ基準5で、決まった入力の並びを `update()` に与える方法（案：`src/debug/` に、入力の並びを配列で持って `update()` を回す確認用の関数を置く。一時的なコードにして確かめたら消す、でもよい）

**受け入れ基準**

| # | 基準 | 確かめ方 |
| --- | --- | --- |
| 1 | 矢印キーと WASD で、8方向に動く | 人（デスクトップ版と Web 版） |
| 2 | Shift を押している間は、決めた速さに落ちる | 人 |
| 3 | 当たり判定の点が常に表示される | 人 |
| 4 | `update()` の中で入力・時間・乱数の関数を呼んでいない | AI：検査スクリプト（T02）が違反を報告しないビルドのログを貼る |
| 5 | 上で決めた方法で、同じ入力の並びを `update()` に2回与えると、自機の位置が同じになる | AI：2回の位置をログに出して比べる |
| 6 | ADR 0003 と design.md §1 のコード例が、入力を渡す形になっている | 人 |
