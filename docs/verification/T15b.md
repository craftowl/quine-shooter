## ADR 0002 のルール3の変更（2026-10-05）

基準1を画面で確かめたときに、作者が「`Vector2 zako` の空白が体に出るのはおかしい。空白をなくしたい」と判断した。人が次のように決め、ADR 0002 のルール3、design.md §4、quine_pack、そのテストを直した。

- コードの空白・タブ・改行を、まとめずにすべて取り除く（`Vector2zako_dummy_velocity(floatspeed){...}` のようになる）
- コードがマスより短いときの繰り返しのつなぎ目に、空白を入れない

下の「確かめた内容」の基準2〜4のログは、変える前のもの（`コード 70 文字。8 文字を切り捨てた`）。変えたあとの生成物と、テストとビルドの結果は次のとおり（AI が 2026-10-05 に実行した出力）。

## わかっている問題（人が条件つきで認めた）

- macOS の make は更新時刻を秒単位で比べるので、直前のビルドと同じ秒の中で入力を書き換えると、quine_pack が動き直さない（基準3）。ふだんの編集では起きない
- `check_sources.cmake` のマーカーの検査は、行を `;` 区切りのリストに分けるので、`\` で終わる行のすぐ次の行のマーカーを見逃し、それより後の行番号も1つずれる（基準5）。前からある検査も同じ分け方をしている（実装のあとのレビューの気づき）

## 確かめられなかったこと

- Windows（Visual Studio のジェネレータ）で、入力を変えたときに生成し直されること（CI は毎回まっさらな状態からビルドするので、一度生成してビルドが通ることまでしか分からない）
