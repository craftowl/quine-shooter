### Chrome 125% の確認

125% で少しにじんで見えたので、canvas が実際のピクセルの境目からずれて、ブラウザが補間しているのではないかと考えた。コンソールで次を実行して確かめた。

```js
(() => { const c = document.getElementById('canvas'); const r = c.getBoundingClientRect(); return [r.left * devicePixelRatio, r.top * devicePixelRatio, r.width * devicePixelRatio, c.width]; })()
```

結果は `[103.00000190734863, 0, 600, 600]`。左端と上端は実際のピクセルの境目にそろっていて（端数は計算の誤差）、表示の幅と中身の幅が同じなので、ブラウザは引き伸ばしていない。150%（18 px）ではくっきり見えたので、125% で柔らかく見えたのは、フォントが 15 px と小さいためと考えられる（T05 で、倍率 1 のまま 1.25 倍（15 px）で見たときも「`0` と `O` が少し分かりづらい」という感想だった）。

## 実装中に起きたこと

- raylib の関数（`FLAG_WINDOW_HIGHDPI`、`GetWindowScaleDPI`、`GetRenderWidth`、`GetRenderHeight`）は `raylib.h` で、`emscripten_get_device_pixel_ratio` は `emscripten.h` で、`emscripten_set_element_css_size` と `EMSCRIPTEN_RESULT_SUCCESS` は `html5.h` で確かめてから使った
- raylib のソース（`rcore.c` の `BeginDrawing`、`BeginMode2D`、`EndMode2D`、`SetupViewport`、`rcore_desktop_glfw.c` の `SetWindowSize` と `FramebufferSizeCallback`、`rcore_web.c`）と、Emscripten の `libglfw.js` の `updateCanvasDimensions` を読んで、方式を決めた
- 確認の間だけ、T05 と同じ3行（`draw_font_sample()`）を `src/main.cpp` に足した。判定のあとで消し、6つの構成をビルドし直した
