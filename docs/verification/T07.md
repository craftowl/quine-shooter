## 実装中に起きたこと

- raylib の関数（`FileExists`、`GetFontDefault`、`DrawText`、`LoadFontEx`、`IsFontValid`、`BeginMode2D`、`WindowShouldClose`）は、取得した `raylib.h` で宣言と引数を確かめてから使った。`emscripten_set_main_loop` は emsdk の `emscripten.h` で確かめた
- raylib のソースで確かめたこと
  - `LoadFontEx` は、ファイルがないと中身が空のフォントを返し、理由を返さない。そこで、先に `FileExists` で確かめて、理由を `File not found` と `Not a valid font file` に分けた
  - `DrawText` は、組み込みのフォントを、文字間 `fontSize / 10` で描く。組み込みのフォントは点で描かれた文字なので、整数倍で描かないとドットの幅がそろわない。そこで、文字の大きさを `10 × 拡大率を四捨五入した整数` px にした
  - `BeginDrawing` は高 DPI の画面で座標を拡大する（`screenScale`）。`BeginMode2D` は拡大しない。そこで、拡大しない `Camera2D`（`zoom` が 1）の中で描き、座標を実際のピクセルにそろえた
- 組み込みのフォントの倍率は、はじめ拡大率を切り下げて決めていた。Retina の画面（2.75 倍）で文字が小さかったので、人が四捨五入にすると決めた（2026-10-02）

### 見つかった不具合：壊れたフォントでゲームが始まる

- 起きたこと：壊れたフォントで起動すると、`FONT: Loaded …` と出て、エラー画面にならずにゲームが始まった
- 原因：raylib 6.0 の `LoadFontFromMemory`（`rtext.c`）は、TTF として読めないとき、失敗を返さずに組み込みのフォントを返す。組み込みのフォントは `IsFontValid` も `texture.id != 0` も満たすので、読めたとみなしていた。この見落としは T05 からあった。T05 の検証ログの「`LoadFontEx` は、ファイルが読めないと中身が空のフォントを返す（組み込みのフォントではない）」は、ファイルがない場合にだけ当てはまる
- 直したこと：返ってきたフォントのテクスチャが組み込みのフォントと同じなら、`Not a valid font file` として扱う。直した後に、壊れたフォントでエラー画面になること、正しいフォントでふつうに起動することを確かめた（上の「起動時のログ」）

### 確認の手順で起きたこと：Web 版の確認用のビルドにフォントが入っていた

- 起きたこと：1回目の Web 版の確認で、フォントがない状態のはずのビルドがフォントを読み込んだ
- 原因：AI が、CMakeLists.txt を戻した後に、コードの修正に合わせて確認用のビルドを作り直した。そのとき CMake が設定をやり直し、`--preload-file` が戻った
- 直したこと：もう一度 `--preload-file` を外して作り直し、すぐに戻した。その後は、確認用のビルドを作り直していない。`2DShooting.data` がないことと、リンクの設定に `--preload-file` がないことを確かめてから、確認し直した
