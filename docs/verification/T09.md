### 受け入れ基準5の確認用プログラム

着手前に決めたとおり、作業用ディレクトリに、ウィンドウを開かない確認用プログラムを置いた（リポジトリには入れていない）。`src/game/player.cpp` をそのままリンクし、下の入力の並びを `update_player` に2回与えて比べた。`main.cpp` の `update()` は `update_player` を呼ぶだけなので、`update()` に与えるのと同じ中身になる。

- 1 ステップは `FIXED_DT`（1/60 秒）。初めの位置は `PLAYER_START_POSITION`（240, 560）
- 動ける範囲は (3.5, 4.5) から (476.5, 635.5) にした。ゲームの範囲（下の「起動時のログ」）に近い値で、確認用プログラムはフォントを読まないため
- 比べたのは、毎ステップの位置（x と y のビット）から作ったハッシュと、最後の位置

## 実装中に起きたこと

### 1. 当たり判定の点の位置：`TextRenderer::glyph_bounds` を足した

- `.` は文字の箱の下の方に描かれるので、箱の位置からは、点の中心が分からない。`TextRenderer` はフォントを外に見せていないので、`main.cpp` から求められなかった
- raylib 6.0 の `DrawTextCodepoint`（`rtext.c`）を読み、文字の点や線が描かれる範囲が `(offsetX, offsetY, アトラスの幅, 高さ) × FONT_SIZE / baseSize` になることを確かめた。`glyphPadding` の分は透明なので含めない。これを返す `glyph_bounds` を足した（人が承認した）
- `A` と `.` は、この範囲の中心を当たり判定の中心に合わせて描く。動ける範囲も、`A` のこの範囲から決める

### 2. macOS のウィンドウの角の丸み

- 起きたこと：デスクトップ版で、画面の隅にいる `A` の大部分が、ウィンドウの角の丸みに隠れて見えにくい（人がスクリーンショットで確かめた）。4つの辺の上では隠れない。Web 版の canvas には丸みがない
- 決めたこと：今のままにする。T23 でゲーム中の画面の並びを決めるときに、動ける範囲を見直す（人が決めた、2026-10-02。tasks.md の T09 と T23）

### 3. 仕様になく AI が決めたこと

- 当たり判定の `.` の色を赤（raylib の `RED`）にした。白の `A` に重ねると見えにくいため
- 起動時に、`A` の大きさと動ける範囲を `TraceLog` に1行出す
- `Player` の `position` の初期値を `PLAYER_START_POSITION` にした

### 4. 行数

- 見込みは約200行。`src/main.cpp` は 40行増え 21行減って 432行
- 新しいファイルは `input`（34行）と `player`（57行）。`text_renderer` に 13行足した
- `main.cpp` は 500行に近づいている
