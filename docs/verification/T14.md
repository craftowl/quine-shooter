## わかっている問題

`/code-review medium`（2026-11-19、Opus 5.5）の指摘は6件。AI が採否の案を出し、人が案のとおりに決めた。

- 直した（基準2・7）
  - 指摘1：`shot.interval` を double で「0 より大きい」と確かめてから float にするので、`1e-50` のような値が float で 0 になって通り、Debug では `shot_interval_updates` の `assert` で止まる。`params.cpp` に `to_positive_float` を足し、float に変えたあとの値が 0 以下なら、範囲の外として失敗にした
  - 指摘2：`shot.bullet_speed` も同じで、速さ 0 の弾になり、プールが満杯になる。`read_speed` で `to_positive_float` を使うようにした。前からある `player.normal_speed` と `player.slow_speed` にも、同じ直しが入る（T14 の範囲を少し越えることを、人が認めた）
  - 指摘5：`spawned` の扱いが `#ifdef DEBUG` / `#else` / `(void)spawned` に分かれていて複雑。`[[maybe_unused]]` にし、`#else` をなくした
  - 指摘6：`shot_interval_updates` が、`interval` が 1 以下という前提をコメントにしか書いていない。`assert` に `interval <= 1.0f` を足した
- 直さない（人が決めた）
  - 指摘3：`interval ÷ dt` がちょうど .5 になる値（0.025、0.075 など）では、丸める向きが float の誤差で決まる。AI が確かめたところ、0.025 は float で割ると 1.5 になって 2 に、double で割ると 1.4999999… になって 1 に丸まった。double にしても向きが逆になるだけで、揺れは消えない。境目はもともとどちらとも言えない値で、結果は毎回同じになる（ADR 0003 は守れる）
  - 指摘4：弾を描く処理が、`draw_char_centered` と同じことをもう一度書いている。描くたびに `glyph_bounds` を呼ばないための形（T17 の敵弾の数を考えた）

直したあとのコードは、`/code-review low` でレビューした（AGENT.md は medium。直したのが 20 行ほどで、レビューが示したとおりの形で、一時的なプログラムと6つのビルドで確かめてあるため、人が low に決めた。T15c2 と同じ扱い）。指摘は 0 件だった。ただし、結果は `(none)` だけで、ツールの使用は1回、時間は約5秒で、差分を読み込んだかはわからない。人がこのままコミットすると決め、`7f30b3b` にコミットした。
