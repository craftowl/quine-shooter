## わかったこと

- サンドボックスの中では gh が使えない（証明書の検証で `x509: OSStatus -26276`）。CI の結果の取得は、人が `!` で gh を実行して行う
- push の前に、コミットの作者を `devowl <devowl@mac>` から craftowl の noreply のアドレスに書き換えた（人の指示。git filter-repo）。ファイルの中身、日付、件名は、書き換えの前と一致することを確かめた。これからのコミットのために、リポジトリに `user.name` と `user.email` を設定した（人が実行）
- 公開したページで、自機が上下に動ける範囲が、ブラウザの表示領域の上に寄って見える（Windows 11 で気づいた）。動ける範囲の計算のずれではなく、canvas の置き方による。`web/shell.html` の CSS は `canvas{display:block;margin:0 auto}` で、canvas は左右の中央に置かれるが、上下は上に寄る。canvas の大きさは 480×640 に、0.25 刻みで切り下げた拡大率を掛けたもの（T05）なので、表示領域の下に余りが出る。背景も canvas も黒なので、余りとの境が見えない。スクリーンショットでは、上に動かした `A` は表示領域の一番上に接し、下に動かした `A` の下には約 118px（スクリーンショットのピクセル）の余りがあった。T03 から同じ置き方で、T11 で変えたところではない。T03 の決定の「中央の `<canvas>`」が上下も含むかは決めていなかった。人が、T23 でゲーム中の画面の並びを決めるときにまとめて見直すと決めた（2026-10-02）。tasks.md の T23 の未決に足した
- 基準4で AI が示したコマンドは `git commit -qam` で、違反の行のほかに、未コミットだった `docs/tasks.md` の変更（T23 の未決の追記）もそのブランチにコミットしてしまった。AI が気づいて後片付けのコマンドを差し替え、main に戻った後に `docs/tasks.md` だけをブランチから取り戻してからブランチを消した。作業ツリーが元どおりであることを確かめた。一時的なコミットを作るときは、`git add <ファイル>` でファイルを指定する
- CI の時間は、キャッシュなしで約1分半（いちばん長い RelWithDebInfo で 1m30s。実行全体で 1m48s）。今のところ、キャッシュを足す必要はない
