### コンパイルの設定（受け入れ基準4）

```
debug:          CXX_DEFINES = -DDEBUG ...          CXX_FLAGS = -g -std=c++20 -Wall -Wextra -Wpedantic -Werror -fno-exceptions
relwithdebinfo: CXX_DEFINES = -DDEBUG ...          CXX_FLAGS = -O2 -g -DNDEBUG -std=c++20 -Wall -Wextra -Wpedantic -Werror -fno-exceptions
release:        CXX_DEFINES = (DEBUG なし) ...     CXX_FLAGS = -O3 -DNDEBUG -std=c++20 -Wall -Wextra -Wpedantic -Werror -fno-exceptions
```

`NDEBUG` は RelWithDebInfo と Release で定義されるので、`assert` が働くのは Debug だけ。

### 受け入れ基準6の計測

| 回 | 最初のフレームの `GetTime()` | `GetTime()` が10秒になるまでの回数 | 最初のフレームから10秒の回数 |
| --- | --- | --- | --- |
| 1 | 記録なし | 590 | 記録なし |
| 2 | 0.079 秒 | 595 | 600 |

- `GetTime()` は `glfwInit()` からの時間で、`InitWindow` の中でウィンドウを作る前から進む。`GetFrameTime()` の積み上げは `InitWindow` の最後から始まる（raylib 6.0 の `rcore.c` と `rcore_desktop_glfw.c` で確かめた）
- そのため「`GetTime()` で10秒」の回数は、初期化にかかった時間の分だけ少なくなる。2回目では、0.079 秒 ≒ 5回分で、595 = 600 − 5 と合う
- 最初のフレームから数えると 600 回で、600±1 に入る
- 基準の「起動してから」を「最初のフレームから」に直す案を出し、人が採用した（tasks.md を直した）

## 実装中に見つかった環境の問題（プロジェクトの外）

- Xcode 26.3 が選ばれていたのに、xcrun が Command Line Tools 27 の SDK（MacOSX 27.0）を返し、Xcode 26.3 のリンカーが SDK 27 を読めずにリンクに失敗した。人が `xcode-select` を Command Line Tools 27 に切り替えて直した
- Command Line Tools の中に、古い版の残り（`usr/include/c++/v1`、2022〜2023年）があり、SDK の libc++ のヘッダを隠していた。人が `c++.old-2023` に名前を変えて直した
