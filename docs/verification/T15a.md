## 確かめた内容

`bad_id.cpp`、`begin_only.cpp`、`dup_b.cpp` の2行目の `3` は、範囲そのものに問題があっても中身を検査することを確かめるために置いた。`markers` の `masks/` の `begin_only.txt`、`nested_b.txt`、`extra.txt` は、範囲を登録しなかった敵のマスクに「対応する QUINE 範囲がない」が出ないことを確かめるために置いた（違反の件数の行で、余分な違反が出ていないことが分かる）。どちらも T15a のレビューの指摘を受けて足した。

## わかっている問題（直さないと人が決めた）

- `QUINE-BEGIN` が入れ子になっていると、それより後の違反の行番号が1つ前にずれる（入れ子の行を範囲の中身に足さないため）。入れ子の違反は出るので、ビルドは止まる（T15a のレビューの指摘。2026-10-03、人が直さないと決めた）

- `ENEMY_DIR`、`MASK_DIR`、テストのディレクトリのパスに、グロブの特殊文字（`[`、`]` など）があると、ファイルが1つも見つからない。quine_pack は「0 体の敵」で成功し、`run_tests.cmake` は「0 件すべて合った」で成功する（T15a のレビューの指摘。低なので直さない、と人が決めた）
- `ENEMY_DIR` に相対パスを渡すと、`file(RELATIVE_PATH …)` の分かりにくいエラーで止まる。T15b のビルドでは絶対パスを渡すので起きない（同じ）
