### 許す DLL の一覧の承認

最初のコミットでは、AI が raylib と GLFW から予想した6つ（`KERNEL32.dll`、`USER32.dll`、`GDI32.dll`、`SHELL32.dll`、`WINMM.dll`、`OPENGL32.dll`）を一覧に入れた。実行 36988816914 で、実際に頼っているのは `OPENGL32.dll` を除く5つだと分かった（GLFW が OpenGL を起動したあとで読み込むためと考えられる）。人が、`OPENGL32.dll` を外して実際の5つにすることを決め、承認した（2026-10-02）。一覧が実際と一致するので、頼る DLL が増えたときに必ず気づける。

同じ実行で、`vswhere` が見つけた `dumpbin` が古い版のツール（14.29、VS 2019 の世代）のものだと分かった。人が、最も新しいツールの版のものを使うように直すと決めた。実行 36990426644 では、VS 2026 のツール（14.51.36231）の `dumpbin` を使っている。

## わかったこと

- MSVC の設定（`/W4 /WX /EHs-c-`、`_HAS_EXCEPTIONS=0`）は、手を入れずに通った。自分のコードに、MSVC だけで出る警告はなかった。T10 で足したのは、ランタイムの静的リンク（`CMAKE_MSVC_RUNTIME_LIBRARY`）、`/utf-8`、Release だけのウィンドウのアプリの設定（`WIN32_EXECUTABLE` と `/ENTRY:mainCRTStartup`）
- 署名していない exe なので、ダウンロードした zip から起動すると「Windows によって PC が保護されました」が出る。「詳細情報」から「実行」を選べば起動する。他人に配るときの案内は、T28 で考える
- Windows は OS の表示スケールを 1 として扱うので（`pixel_ratio` が 1）、拡大率の最小は、ADR 0008 の「OS の座標で 1.0」ではなく、実際のピクセルで 1.0 になる。作者の環境（1920×1080、150%）では、拡大率がたまたま 1.5（OS の座標でちょうど 1.0）になるので、差は出ない。表示スケールが大きく画面が小さい PC（例：1366×768 で 150%）では、文字がほかのアプリより小さく見えるはず（確かめていない）。ADR 0008 に書いた。直すかは、T10 の決定どおり別に決める
- Windows の Debug のビルドで、OS のライブラリの確保が operator new を通るかは、確かめていない（`main.cpp` の Windows の分岐は、今は判定しない）。T10 の受け入れ基準には入っていない
- CI の時間は、キャッシュなしで1分〜1分40秒ほど（いちばん長い Release で 1m38s）
